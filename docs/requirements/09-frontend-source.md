# 前端产品与交互阶段性真源

> 文档职责：定义 Ant Design Pro 使用边界、导航、页面归属、长页面交互、动态能力、状态展示、错误反馈和前后端契约。
> 本文件不重复业务规则；具体字段和状态必须引用对应业务真源及后续页面/API 对照表。

## 1. 工程基座

采用 Ant Design Pro v6.0.2 的 Simple Mode，固定 release `v6.0.2` 和 commit `2b453c67b535b76f5f95d6542397a4b987b61de2`，不跟随 `master`。底层基线为 React 19、TypeScript、Umi Max 4 和 Ant Design 6。

沿用：

- ProLayout、ProComponents、Ant Design、官方图标、登录布局和基础异常页。
- Umi Router、initialState/model、request、React Query 和 OpenAPI 插件。
- 表格、表单、Tabs、弹窗、抽屉、通知、主题 token 和构建配置。

模板导入和精简必须可审计：

1. 在独立阶段 worktree 导入固定 commit 的完整可运行应用基线，保留 MIT License，并先提交未精简基线。
2. 执行官方 `npm run simple`，审查其删除页面、路由和依赖的实际 diff，再提交 Simple Mode 基线。
3. 官方 Simple Mode 仍保留 Welcome、Admin 和查询表格示例；继续删除这些示例、Mock、注册页、上游品牌、分析脚本和与产品无关的外链，并在导入边界排除 Cloudflare Worker。
4. Simple Mode 会移除 `@ant-design/plots`、D3 和 TopoJSON；第一阶段不保留无用图表依赖，质量仪表盘阶段按真实图表需求重新引入精确版本并补测试。

状态职责固定：

- 服务端列表、详情、轮询和缓存状态使用 React Query，query key 必须包含资源 ID、筛选和配置修订。
- 当前管理员和全局布局使用 Umi initialState/model；第一版 Umi access 只实现登录/强制改密守卫，不定义虚假 RBAC。
- 最近访问等纯客户端偏好可使用小型 Umi model/local persistence，只保存 ID、时间和显示偏好，不保存业务快照。
- 表单草稿默认留在页面/feature 内；不建立包含所有 API、业务实体和页面状态的巨大 store。

新增代码按 `features/<domain>` 组织，`src/pages` 只做路由入口和页面编排。Ant Design Pro 默认视觉不是最终视觉真源；最终模板未提供时先保证业务骨架，后续通过 Ant Design token、CSS Modules 或 `antd-style` 调整，不改变页面/API 契约。

## 2. 前端强制原则

- 页面、字段、按钮、状态、错误码和下拉都能追溯到后端资源/API。
- `@umijs/max-plugin-openapi` 读取版本控制中的后端 OpenAPI，生成 `src/services/ragApi` 类型/client；该目录是接口结构真源，禁止手写或复制重复 DTO。
- 所有生成请求统一经过 Umi `request` 配置处理 Cookie、CSRF、traceId、超时和错误映射；页面不得另建第二套 Axios/fetch client。
- capability 下拉在前端真实显示，但选项从后端获取；前端保存 code/ID，不保存中文展示名作为关系。
- 所有写操作后端校验，前端校验只为体验。
- 任务状态来自业务 task API，不依赖 Celery 内部状态。
- 路由参数必须使用明确 ID 名，不使用通用 `documentId`。
- 页面刷新、深链接和浏览器返回后仍能还原当前资源和 Tab。
- 任何失败都展示 `message + traceId`；高级详情显示稳定错误码，不显示堆栈和密钥。

## 3. 固定导航

侧边栏顺序不可随页面变化：

1. 数据清洗与解析。
2. 仪表盘。
3. 知识库管理。
4. 机器人管理。
5. 模型配置。
6. 渠道接入。
7. 任务中心。
8. 问答日志。
9. 系统设置，固定在问答日志下方和侧栏底部区域。

导航要求：

- “数据清洗与解析”固定顶部第一业务入口。
- “知识库管理”和“机器人管理”右侧同时提供 `+` 快捷创建图标和展开箭头。
- `+` 直接进入创建页；展开箭头显示最近访问、全部列表等快捷项，两者点击区域和事件独立。
- 图标按钮使用现有图标库并带 Tooltip 和可访问名称。
- 菜单不做第一版动态权限，但路由仍由登录守卫保护。

## 4. 页面地图

### 数据清洗与解析

- `/parsing`：Tabs 为上传与解析任务、处理前后对比、已解析数据源。
- `/parsing/sources/:dataSourceId`：数据源和解析版本历史。
- `/parsing/versions/:parsedSourceVersionId`：处理前后对比详情。

### 知识库

- `/knowledge-bases`：列表。
- `/knowledge-bases/create`：六区长表单。
- `/knowledge-bases/:knowledgeBaseId`：详情 Tabs。

### 机器人

- `/bots`：列表。
- `/bots/create`：创建长表单。
- `/bots/:botId`：详情/编辑/问答测试 Tabs。

### 其他

- `/models`：供应商和模型 Tabs/主从视图。
- `/channels`：Webhook/API 实例列表和详情。
- `/tasks`：任务列表；任务详情抽屉可由 query 参数深链。
- `/chat-logs`：问答日志列表；Trace 使用右侧抽屉和全屏详情。
- `/settings`：MinerU、日志保留、系统运行和管理员安全设置。
- `/dashboard`：概览、运行健康、在线指标和质量评测。

## 5. 少页面原则

- 创建/复杂编辑使用一个可滚动长页面、分区锚点和折叠面板。
- 相关子视图使用 Tabs，不拆成大量菜单。
- 短详情、失败原因、任务阶段、单条引用使用抽屉。
- 创建确认、危险操作、少字段编辑使用弹窗。
- 不把完整复杂表单塞进窄抽屉。
- 页面内容区是唯一主滚动容器；避免多层滚动条。
- 侧边栏、顶部栏固定，长表单底部保存操作条使用 sticky 并保证不遮挡最后一项。

## 6. 数据解析交互

上传区：

- 拖拽/选择文件，显示 capability 支持格式和限制。
- 每个文件独立展示校验、上传、解析状态和错误。
- 解析参数折叠区默认使用全局配置，可临时覆盖。
- 点击“开始解析”才提交；重复文件显示复用/强制重解析选择。

处理前后对比：

- 左原文、右结果，页码和 block 联动。
- 右侧 Tabs：Markdown、Blocks、OCR、表格、公式、Assets、产物清单。
- 无 boundingBox 或降级解析时明确提示，不显示虚假高亮。

已解析数据源：

- 列表/版本、被引用数量、质量状态、重新解析和删除。
- 新版本完成后显示“知识库仍使用旧版本”的说明和跳转。

## 7. 知识库交互

列表支持搜索、筛选、稳定排序和分页。状态展示从后端状态摘要 DTO 获取，不在前端自己组合关键业务逻辑。

创建页六区：基础信息、已解析数据源、Embedding/向量索引、分块/索引结构、检索/重写/重排、确认。

- 数据源选择器只能选择解析完成版本。
- 所有数值都可直接输入，并按 schema 显示默认、范围和单位；不能用固定不可编辑值冒充参数。
- 条件字段按策略显示，例如关闭重排时模型显示“无”，选择后才出现类型匹配模型。
- capability 或模型不存在时后端禁止保存；前端在提交前明确定位到错误分区。
- 点击最终“创建并构建”后跳到详情构建进度，不在页面等待完成。

详情显示活动代次、正在构建代次和未发布配置，三者不能混成一个状态。构建期设置保存后显示“需要构建新索引”，查询期设置保存后显示“新请求已生效”。

## 8. 机器人交互

- 绑定知识库多选项展示可用性、部分就绪警告和活动 generation 时间。
- priority 使用数值选择 1-10并解释“1 最高”，不靠拖拽顺序隐式保存。
- 跨库策略第一版只显示“排名融合（RRF）”，普通用户不看到无效模式。
- 机器人最终上下文条数字段显示为 `finalContextTopK`，与单知识库检索的 `finalTopK` 分开；token 预算、记忆和兜底按业务真源显示。
- 系统提示词可编辑，保留后端安全指令提示但不展示/允许覆盖隐藏系统规则。
- 测试页显示回答、引用、各知识库状态、跨库贡献、上下文预算和 Trace。

## 9. 模型和 MinerU 配置

- 供应商“保存”和“测试连接”是两个按钮和两个状态。
- API Key/Token 不回显；留空表示不替换，覆盖前二次确认。
- 模型按类型真实测试，列表显示 enabled 和 verificationStatus 两列。
- 被引用模型的危险字段只读，详情展示引用清单。
- MinerU 设置位于系统设置，不放在模型配置；连接测试明确提示会调用云 API、可能消耗额度。

## 10. 动态能力表单

前端实现 `CapabilitySelect` 和 `SchemaForm`：

- capability API 返回选项、enabled、version、configSchema、uiSchema。
- enabled=false 默认显示为 disabled 并展示 unavailableReason，方便用户理解后续扩展；不允许保存。
- 生产环境可由后端 `visible=false` 隐藏纯内部能力。
- 切换策略时清除不再适用的字段或明确发送 null，不能把隐藏旧值悄悄提交。
- schema 加载失败时整个表单禁止保存并显示 traceId，不能退回前端旧缓存继续提交。
- 保存时带 capability version，后端发现过期返回 409 并要求重新加载。

业务状态、删除语义和固定枚举仍由 OpenAPI enum/字典端点提供，不把所有东西都滥用 capability。

## 11. 异步任务体验

- 创建解析、构建、异步问答后立即返回 operationId。
- 详情页前 60 秒每 2 秒轮询，之后每 5 秒；页面后台时降为 15 秒。
- 任务进入终态、页面离开或组件卸载时停止轮询并取消请求。
- 同一 operation 在多个组件中通过 React Query 的单一 query cache 共享，不重复轮询。
- 网络断开指数退避，恢复后继续，不把临时网络失败改成业务任务失败。
- 第一版不用 WebSocket/SSE。
- 任务进度只作展示；最终状态由 operation.status 决定。

## 12. 列表、筛选和 URL 状态

- 服务器端分页，默认 pageSize 20，可选 20/50/100。
- 搜索防抖 300ms。
- 筛选、排序、分页、当前 Tab 写入 URL query，刷新可恢复。
- 请求竞态通过 AbortController 或 query key 解决，旧响应不能覆盖新筛选结果。
- 所有列表有 loading、empty、error、partial-data 状态。
- 危险操作完成后保持合理页码；当前页为空时回到上一页。

## 13. 表单和并发冲突

- 表单使用后端 schema 和同源校验信息。
- 离开未保存表单时提示。
- 保存携带 `expectedRevision`。
- 409 冲突时显示“资源已被更新”，提供重新加载；第一版不做自动字段合并。
- 提交期间禁用重复按钮，但幂等仍由后端保证。
- API 422 的字段错误映射到具体分区和字段，并保留 traceId。

## 14. 危险操作

停用、删除、换 Embedding、全库重建、API Key 轮换和日志清理必须使用二次确认。

确认内容展示真实影响摘要。删除不要求输入名称，但必须勾选/点击明确确认。按钮文案必须写具体动作，例如“删除知识库”，不能只写“确定”。

## 15. Trace 展示

问答日志列表只显示排查所需摘要；详情按阶段折叠：

1. 请求和会话。
2. 机器人/知识库/模型快照。
3. 指代和查询重写。
4. 每库召回、过滤、融合和重排。
5. 跨库 RRF。
6. token 预算和最终上下文。
7. Prompt/模型响应。
8. 引用校验。
9. 错误、重试和耗时。

默认脱敏；管理员点击“查看敏感正文”需再次确认并写审计日志。禁止展示密钥、签名 URL、本地绝对路径。

## 16. 可访问性和响应式

- 第一版后台最低支持宽度 1280px；1024-1279 可用但表格可横向滚动；小于 1024 显示不支持管理操作提示，不承诺完整移动后台。
- 所有表单有 label、错误关联和键盘焦点。
- 图标按钮有 Tooltip/aria-label。
- 焦点态清晰，不能仅靠颜色传达状态。
- 长文本、模型名、sourcePath、错误码可换行/省略并提供完整 Tooltip。
- 固定宽度控件和表格列有 min/max，动态状态不引发布局跳动。

## 17. 前端错误处理

- 401 管理员 Token 失效 -> 清理登录态并跳转登录；外部渠道 401 不走前端后台逻辑。
- 403 -> 无权限提示（后续 RBAC 预留）。
- 404 -> 资源不存在/已删除状态页。
- 409 -> 并发或幂等冲突专用处理。
- 422 -> 字段错误。
- 429 -> 显示重试时间。
- 5xx -> 通用错误、traceId 和重试按钮。

不能用 toast 覆盖所有错误。需要用户修正的数据放在字段/页面，后台任务失败放任务详情，短暂成功才用 toast。

## 18. 前端验收

- 导航顺序、顶部数据解析、知识库/机器人 `+` 和下拉、底部系统设置在所有页面一致。
- 长页面只有一个主滚动容器，sticky 操作栏不遮挡字段。
- 每个可见控件在页面/API 对照表中有后端对应。
- Umi OpenAPI 重新生成后无手写 DTO 冲突，重复生成无 Git diff。
- 动态下拉只保存真实 enabled 能力，disabled 不能提交。
- 页面刷新能恢复资源、Tab、筛选和 operation 状态。
- 并发保存冲突不会覆盖别人的修改。
- 关键页面在 1280、1440、1920 宽度无重叠、截断和不可达操作。
